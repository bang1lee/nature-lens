# 네이처렌즈 식물 식별 흐름 — 설계 및 검증 계획

작성일: 2026-09-29. 상태: **검토용 제안, 구현 승인 전**.
이번 작업은 문서 작성과 공식 자료 확인만 수행했다. 앱 코드 변경, 새 서비스 가입, 식별 API 호출, 실사진 전송, 정확도·성능 시험은 수행하지 않았다. 아래 수치와 API v2는 제안이며 현재 동작이나 측정 결과가 아니다.

## 0. 현재 프로젝트와 권장 방향

현재 Next.js 정적 웹 + Mac/Android용 Tauri 골격, IndexedDB 관찰 기록, Supabase 로그인, 별도 Node 식별 게이트웨이를 재사용한다. Mac 설치형 골격과 Android 실기기 검증 완료는 서로 다른 상태다. Android 식별 UX·권한·성능은 별도 검증이 필요하다.

|---|---|---|
| 입력 | 촬영/파일 선택, JPEG·PNG·WebP, 원본 15MiB 제한 | 촬영 미지원 시 선택 대안, 품질 안내, 같은 식물 추가 사진 |

기존 변경 사항은 보존한다. 기존 테스트 통과 여부는 새 식별 정확도를 증명하지 않는다.

**권장:** Pl@ntNet + 기존 게이트웨이 + 버전이 있는 한국어 식물 정보 목록. 새 식별 업체나 생성형 설명 API는 우선 도입하지 않는다. 목록 구축은 필요한 신규 작업이며 이미 존재하는 기능이 아니다.

사진 선택만으로 외부에 전송하지 않는다. 이름을 몰라도 관찰을 저장할 수 있다. 후보 선택은 사용자 선택 기록이며 전문가의 확정 판정이 아니다. 기존 보호종·공개 동의·위치 공개 설정을 자동 변경하지 않는다.

### 입력 정책 제안

- 원본: JPEG/PNG/WebP, 장당 15MiB 이하. 확장자·MIME뿐 아니라 디코딩 결과로 검사한다. HEIC는 초기에는 변환 안내, GIF/동영상/움직이는 이미지는 제외한다.
- 입력 해상도: 원본 최대 48MP 제안. 디코딩 전에 헤더로 확인하고, 상한 초과 시 작은 사본 선택 안내. 실제 Mac/저사양 Android의 메모리 시험 후 조정한다.
- 전송: JPEG, 긴 변 최대 1600px, 품질 0.85를 출발점으로 하되 0.9와 정확도/용량 비교. 장당 2MiB, 최대 3장 합계 4MiB. 줄일 수 없으면 전송 전에 안내한다. 원본을 덮어쓰지 않는다.
- 서버: 본문 최대 5,650,000바이트(JSON/base64 포함), 디코딩 후 합산 4MiB, 장당 16MP, 프레임 1개. 경계값 테스트로 JSON 여유 공간을 검증한다. 순차 디코딩과 동시 요청 제한으로 메모리 폭주를 막는다.
- 품질: 짧은 변 800px 미만은 경고 출발점. 흐림·과다/부족 노출은 경고만 제공하고 임계값은 표본으로 정한다. 저해상도 확대는 정보를 복원하지 않는다. 품질 검사는 종 식별과 별개다.
- 사진에 여러 식물이 있으면 사용자가 한 식물을 자른다. 자동 개체 분리/탐지는 초기 범위에 없다. 후보가 여러 개라는 이유로 여러 식물이 찍혔다고 판정하지 않는다.
- 추가 사진은 **같은 개체**의 꽃·열매·잎·전체 모습 중 가능한 것을 요청한다. 없는 꽃을 요구하거나 식물을 훼손하도록 유도하지 않는다.

Pl@ntNet은 같은 개체의 복수 사진을 지원하고 작은 사진의 성능에 제약을 안내한다. 앱의 3장 제한은 사용성과 전송량을 위한 별도 제안이다. [공식 FAQ](https://my.plantnet.org/doc/getting-started/faq)

## 2. 각 구성 요소의 역할

| 구성 요소 | 책임 | 책임 밖 |
|---|---|---|
| 공통 촬영/선택 화면 | 권한 안내, 입력·미리보기·품질 경고, 키보드/터치 접근성 | 종 이름 확정 |
| 기기 전처리 | 회전 적용, 자르기, 압축, EXIF 제거, 세션 사진 관리 | 원본 앨범 수정 |
| 식별 클라이언트 | 동의 버전, 요청 ID, 사진 revision, 진행/취소/재시도 | 비밀 API 키 보관 |
| 기존 Node 게이트웨이 | Supabase 토큰 검증, 동의·용량·형식 재검사, 한도·중복 제어 | 원본 사진 장기 보관 |
| Pl@ntNet 어댑터 | 공급자 요청·응답 검증, 시간 제한, 모델 버전 수집 | 한국 표준 국명 보장 |
| 분류군 대응표 | 공급자 ID/학명 → 내부 taxonId → 채택 학명·국명 | 문자열 유사도만으로 자동 확정 |
| 식물 정보 목록 | 쉬운 설명, 관찰 특징, 비슷한 종 비교, 출처·갱신일 | 사진에서 확인하지 않은 특징을 봤다고 주장 |
| 결과 정책 | 점수·후보 간 격차·품질로 비교/보류 결정 | 점수를 정답 확률로 표시 |
| 로컬 관찰 저장 | 선택한 이름·대표 사진·출처 버전, 기존 충돌 방지 | 자동 공개/위치 전송 |
| 운영 계측 | 단계별 지연, 공급자 시도 수, 추정 비용·오류율 | 사진·GPS·인증 토큰 로그 |

### 이름과 정보 연결

1. 응답의 공급자 식별자(있을 때), 학명, 저자명/분류 단계, 모델 버전을 보존한다. 현재 어댑터가 버리는 필드는 확장해야 한다.
2. 검수한 교차표로 내부 `taxonId`에 연결한다. 채택 학명과 동의어를 별도 관리한다. 아종·변종·교잡 표기를 무작정 제거하지 않는다.
3. 동일 이름 충돌이나 분류 체계 불일치는 `ambiguous`, 대응 없음은 `unmapped`로 둔다. 공급자 ID도 검증 없이 국내 목록의 ID와 같다고 보지 않는다.
4. 국명이 검증되면 국명 + 학명을 표시한다. 없으면 학명 + “한국어 이름 확인 중”. 한글 응답이라는 이유만으로 표준 국명이라고 표시하지 않는다.
5. 설명은 출처를 검수한 짧은 문장, 관찰 포인트 2~3개, 비슷한 종과의 차이, 정보 출처로 구성한다. 미등록 정보는 “아직 준비되지 않았어요”. 생성형 모델로 빈 내용을 채우지 않는다.
6. 각 정보에 `sourceUrl`, 원자료 버전/일자, 내부 목록 버전, 이용 조건, 검수 상태를 둔다. 일반적인 종 설명과 실제 사진에 보이는 특징을 구분한다. 식용·약용 판단은 이 기능의 목표에 포함하지 않는다.

초기 후보 자료는 산림청의 [표준식물기본정보 식물분류체계](https://www.data.go.kr/data/15123047/fileData.do). 포털에 CSV·이용허락 제한 없음으로 표시되지만 일부 결측과 오래된 기준일이 있어 **완성된 국명·설명 목록으로 간주할 수 없다**. 실제 파일의 필드, 대상 종 수, 최신성, 국명 포함 여부를 확인한 뒤 채택한다. 국명이나 설명이 부족하면 국립생물자원관 등 공식 자료를 보완 후보로 조사하고 해당 자료의 재사용 조건을 개별 확인한다. 웹 공개와 재배포 허용은 다르다.

### 사진·키·요청 데이터 보관 제안

| 데이터 | 위치·기간 | 삭제/통제 |
|---|---|---|
| 아직 저장하지 않은 사진 | 기기 메모리, 세션 동안 | 닫을 때 미저장 안내 후 해제; 앱 종료 시 복구 보장 없음 |
| 관찰 대표 사진 | 현재 IndexedDB, 사용자가 저장한 동안 | 관찰 삭제로 삭제; 기기 앨범 원본·별도 백업은 별개임을 안내 |
| 추가 사진 | 초기에는 세션에서만 사용 | 세션 종료 시 해제; 영구 저장은 스키마/백업 확장 후 별도 기능 |
| 게이트웨이 사진 | 처리 중 메모리 | 파일·객체 저장소·요청 본문 로그에 기록하지 않음; 메모리 해제는 보안 덮어쓰기 보장과 다름 |
| 결과 캐시 | 서버, 사용자별 15분 제안 | 사진 없는 결과 JSON, TTL 삭제; 인증된 요청자만 조회 |
| 한도/요청 원장 | 서버, 35일 제안 | 사용자 ID와 요청 ID 최소화, 만료 정리; 계정 삭제 시 식별 가능 기록 처리 정책 마련 |
| 집계 지표 | 사용자·사진 없는 일/모델별 집계 | 원장과 분리, 보관 기간 운영 정책에 명시 |
| 공급자 키 | 서버 비밀 저장소 또는 로컬 비추적 환경 변수 | 웹 번들·Tauri 앱·Git·오류 메시지에 포함 금지, 회전 가능 |

Pl@ntNet 약관은 전송 사진을 처리 중 휘발성 메모리에만 두며 요청 이력은 별도로 보관한다고 설명한다. 따라서 “모든 흔적 즉시 삭제”라고 안내하지 않는다. URL 입력 대신 이미지 바이트를 보내고, 전송 대상·목적·이력 정책을 동의 화면에 연결한다. [공식 약관](https://my.plantnet.org/terms_of_use)

키가 공급자 URL 쿼리에 실리는 현재 방식은 프록시/APM에서 쿼리와 인증 헤더를 반드시 마스킹해야 한다. 출처가 허용되지 않은 웹 요청, 만료 토큰, 다른 사용자의 요청 조회를 서버에서 거부한다. 위치·앨범 경로·파일 원래 이름은 식별 API에 보내지 않는다.

## 3. API 요청·응답 예시 — 제안 계약

기존 `/identify`는 현재 계약을 유지하고, 다중 사진·새 상태는 `/v2/plant-identifications`로 분리한다. 아래는 **실제 응답이 아닌 문서용 예시**이며 base64와 정보 문장은 자리 표시자다.

### 요청

`POST /v2/plant-identifications`, `Authorization: Bearer <Supabase 사용자 토큰>`, `Content-Type: application/json`

```json
{
  "requestId": "195e17ea-9d60-4a44-8885-6f3565070192",
  "inputRevision": 1,
  "images": [
    {"imageId": "photo-1", "dataUrl": "data:image/jpeg;base64,<JPEG_BYTES>", "organ": "auto"}
  ],
  "consent": {"transmission": true, "noPeople": true, "policyVersion": "2026-09-29-draft"}
}
```

`requestId`는 UUID, `inputRevision`은 양의 정수다. 사진은 1~3장, 부위는 auto/leaf/flower/fruit/bark 허용 목록을 사용한다. 미저장 사진도 식별할 수 있도록 observationId는 필수가 아니다.

### 정상 결과: HTTP 200

실제 종 이름을 구조 설명에 사용했지만 ID·점수·설명·시간은 예시이며 검수된 식물 데이터가 아니다.

```json
{
  "requestId": "195e17ea-9d60-4a44-8885-6f3565070192",
  "inputRevision": 1,
  "state": "candidates",
  "decision": "compare",
  "needsHumanReview": true,
  "provider": {"name": "plantnet", "modelVersion": "example-only"},
  "catalogVersion": "demo-v1",
  "candidates": [
    {
      "candidateId": "candidate-1",
      "taxonId": "demo-taxon-1",
      "scientificName": "Acer palmatum",
      "koreanName": "단풍나무",
      "nameStatus": "matched",
      "rankingScore": 0.72,
      "profile": {
        "status": "reviewed",
        "summaryKo": "검수한 쉬운 식물 설명이 들어가는 자리입니다.",
        "observationPoints": ["검수한 관찰 포인트가 들어가는 자리입니다."],
        "sourceUrl": "https://example.org/plant-profile",
        "reviewedAt": "2026-09-29"
      }
    }
  ],
  "nextAction": "compare_or_save",

}
```

`rankingScore`는 내부 평가용 순위 점수다. 화면에 “정확도 72%”로 바꾸지 않는다. 검수된 정보가 없으면 profile은 `status: unavailable`, 설명/출처는 null이며 UI도 이를 표시한다. `nameStatus`는 matched/unmapped/ambiguous다. 후보 목록은 최대 3개다.

### 불확실한 결과: HTTP 200

```json
{
  "requestId": "195e17ea-9d60-4a44-8885-6f3565070192",
  "inputRevision": 1,
  "state": "uncertain",
  "reason": "close_candidates",
  "needsHumanReview": true,
  "candidates": [],
  "nextAction": "add_photo",
  "photoAdvice": "같은 식물의 잎이나 꽃을 가까이서 한 장 더 찍어 주세요."
}
```

실제 `uncertain`은 비교할 근거가 있으면 최대 3후보를 함께 반환할 수 있다. 공급자 거절/후보 부재는 `state: no_match`, `reason: provider_rejected_or_no_species`, 빈 후보를 반환한다. 404 하나로 비식물이라고 단정하지 않는다. 이는 현재 구현의 수정 제안이다. [공식 FAQ의 거절 설명](https://my.plantnet.org/doc/getting-started/faq)

### 오류: HTTP 413 예시

```json
{
  "requestId": "195e17ea-9d60-4a44-8885-6f3565070192",
  "error": {
    "code": "IMAGE_TOO_LARGE",
    "message": "전송할 사진 크기를 줄여 주세요.",
    "retryable": false,
    "action": "choose_smaller_photo"
  }
}
```

공통 오류: 400 INVALID_REQUEST/INVALID_IMAGE, 401 AUTH_REQUIRED, 403 CONSENT_REQUIRED, 413 IMAGE_TOO_LARGE, 415 UNSUPPORTED_FORMAT, 409 REQUEST_ID_REUSED/OBSERVATION_CHANGED, 429 DAILY_LIMIT, 502 PROVIDER_ERROR, 503 IDENTIFICATION_DISABLED, 504 PROVIDER_TIMEOUT. 입력 검사 순서와 코드 우선순위를 계약 테스트로 고정한다. 공급자 키·원문 오류·내부 경로를 응답에 노출하지 않는다.

### 공급자 연결 및 중복 제어

- 서버에서 현재 `POST https://my-api.plantnet.org/v2/identify/all` 어댑터를 확장한다. 사진별 multipart `images`, 대응하는 `organs`, 후보 3개, `no-reject=false`, `lang=ko`. 공급자 키는 서버에서만 붙인다. 공급자 계약의 필드·배열 순서·에러는 구현 전 공식 OpenAPI와 대조한다.
- 사용자가 사진을 바꾸면 revision을 증가시킨다. 늦게 도착한 이전 revision의 응답은 적용하지 않는다. 기존 관찰 재식별은 저장 시 updatedAt 충돌 검사도 유지한다.
- 인증 → 크기 상한/속도 제한 → 이미지 검사 → 일일 식별 한도 예약 → 공급자 호출. 잘못된 사진은 유료 시도를 만들지 않도록 한다. 현재 원장은 이미지 검사 전 예약하는 구조여서 변경이 필요하다.
- `(userId, requestId)`와 전처리 이미지·설정의 지문을 묶는다. 같은 ID+같은 입력은 실행 중 202, 완료 후 15분 동안 캐시된 200을 반환한다. 같은 ID+다른 입력은 409다. 지문은 보관 기간이 제한된 내부 데이터로 취급한다.
- `GET /v2/plant-identifications/{requestId}`: 본인 요청만 조회. 처리 중 202 + Retry-After, 완료 200, 만료 410, 다른 사용자/없는 ID는 404. 캐시 만료 후에도 남은 원장으로 같은 요청을 다시 유료 실행하지 않는다.
- 공급자 전송 후 타임아웃/서버 재시작은 `outcome_unknown`으로 기록한다. 클라이언트는 상태 조회만 자동 재시도한다. 새 유료 요청은 사용자 버튼으로만 시작하고 추가 한도 사용 가능성을 표시한다. 네트워크 실패를 무조건 재전송하지 않는다.
- 현재의 SQLite 원장은 상태/결과 캐시 없이 중복 ID를 409로 거부한다. 위 동작은 새 설계다. 단일 서버의 영속 디스크를 전제로 하며 여러 인스턴스로 늘릴 때는 공유 원장으로 이전해야 한다.

| 불확실 | 비슷한 식물이 있어 추가 사진이 필요해요 | 같은 개체 사진 추가, 미확인 저장 |
| 후보 없음/비식물 가능 | 식물 후보를 찾지 못했어요 | 사진 확인, 다시 촬영, 일반 관찰 저장 |
| 오프라인 | 인터넷 연결 후 식별할 수 있어요 | 로컬 초안 저장, 수동 재시도 |

| 한도 초과 | 오늘 식별 가능한 횟수를 사용했어요 | 로컬 저장, 서버가 알려준 재개 시각 확인 |

Mac: 파일 선택·키보드 탭/Enter/Escape·포커스 복원 검증. Android: 카메라/사진 선택 취소·권한 거부·회전·백그라운드 복귀·메모리 부족 검증. 웹은 브라우저별 촬영 지원 차이에 대비한다. 기존 종이 질감 디자인을 재사용하되 사진과 이름의 대비를 우선하고, 대기 애니메이션은 동작 줄이기 설정을 따른다. 스크린리더에 단계 변경을 알리고 오류 후 입력을 유지한다.

## 5. 식별 품질·응답 시간·비용 평가 방법

### 식별 평가

제안 표본: 목표 지역에서 자주 관찰할 100종 × 서로 다른 개체 5개 = 식물 500개체, 비식물 100장, 여러 식물 100장. 식물 개체마다 가능하면 1~3장. 접근 권한과 이용 동의를 확보하고 전문가 검수 라벨, 허용 동의어, 판별 불가 라벨을 만든다. 종 구성은 출시 대상 지역/계절/관엽식물 비중을 확정한 뒤 정한다.

식물 표본 절반은 점수 정책 보정, 절반은 잠근 평가용으로 분리한다. 같은 개체·연속 촬영·중복 이미지는 양쪽에 나누지 않는다. 장소/촬영자 단위 편중도 확인한다. 공급자 학습 자료와의 중복을 완전히 확인할 수 없다는 한계와 드문 종의 표본 부족을 보고한다. 대조군도 보정/평가를 분리한다.

| 평가 항목 | 방법 | 잠정 출시 기준 — 실측 아님 |
|---|---|---|
| 후보 검색 | 정답이 첫 후보/상위 3후보 안에 있는 비율 | 평가 식물 Top-3 ≥85%, 종별 평균도 별도 보고 |
| 우선 후보 안내 | 강한 표현을 허용한 집합의 정확도와 적용 비율 | 정확도 ≥95%, 95% 신뢰구간 하한 ≥90%, 적용 비율 ≥40% |
| 비식물 | 비식물에 식물 후보를 잘못 제시한 비율 | ≤5%, 신뢰구간과 원본 건수 병기 |
| 복수 개체 | 자르기 안내를 이해하고 대상을 선택하는지 | 대표 실패 유형 전부 검증; 자동 분리 정확도를 주장하지 않음 |
| 한국어 이름 | 검수 정답과 taxonId·국명 연결 대조 | 평가 대상의 잘못된 연결 0건; 미연결률 별도 공개 |
| 설명 | 출처·국명·특징과 문장 대조 | 검수 대상 오류 0건, 미검수 설명 노출 0건 |
| 추가 사진 효과 | 같은 개체 1장과 최대 3장 결과를 짝지어 비교 | 정확도 개선·지연·호출 비용을 함께 보고 |
| 기권 정책 | 흐림/근접 종/목록 밖 종에서 보류하는지 | 오류를 숨기지 않고 coverage와 오판을 함께 보고 |

기존 0.2는 보정된 기준이 아니다. 보정 표본으로 상위 점수와 1·2위 격차의 기준을 정하고 평가 표본에는 다시 맞추지 않는다. 작은 표본에서 기준을 만족하지 못하면 범위를 좁히거나 모든 결과를 비교 후보로만 제공한다. “정확도 95%”를 전체 식물 인식 성능으로 홍보하지 않는다. 모델/목록 버전이 바뀌면 고정 회귀 세트로 재평가한다.

### 시스템·개인정보 검증

모의 공급자 응답으로 먼저 검증한다: 성공/빈 후보/404/429/5xx/손상 JSON/시간 초과, 중복 동시 요청, 타 사용자 조회, 토큰 만료, 동의 누락, 위조 MIME·손상·초대형 픽셀·본문 초과, EXIF 제거, 비밀키/사진 로그 부재, 삭제/TTL, 사진 변경 중 늦은 응답, 저장 충돌. 저장/백업 스키마 변경은 이전 데이터 마이그레이션·복원도 검증한다.

그다음 동의받은 표본만 실제 API로 확인한다. 단위·계약 테스트, 웹 상호작용 테스트, Mac 앱과 Android 실기기 시험을 구분하여 기록한다. 실제 공급자 비용이 드는 시험의 건수와 예산은 실행 전에 정한다. 이 문서에서는 시험을 실행하지 않았다.

### 시간과 비용 계측

- 클라이언트: 식별 버튼 → 전처리 완료 → 전송 → 결과 렌더까지 단조 시계로 측정. 카메라를 열어 고민한 시간은 별도 UX 지표다.
- 서버: 인증, 이미지 처리, 한도 예약, 공급자, 정보 연결, 직렬화 시간을 각각 측정. 서버·기기 시계를 빼서 구간 시간을 만들지 않는다.
- p50/p95와 실패율을 기기·네트워크·사진 수·모델별로 보고한다. 잠정 목표는 전체 p50 ≤5초, p95 ≤12초. 공급자 20초 제한을 출발점으로 전체 서버 25초/클라이언트 30초 예산을 검증한다. 목표 초과 시 원인을 확인하고 수치를 재합의한다.
- 비용 원장: 요청 ID, 공급자 시도 수, 결과 상태, 모델, 가격표 버전, 요금제, 예상 과금 단위, 캐시 여부. 로컬 한도 사용량과 공급자 과금량은 다르다. 타임아웃·404의 실제 과금 여부는 대시보드/계약으로 대조하고 미확인은 unknown으로 둔다.
- `변동 추정 비용 = 확인된 과금 단위 × 적용 단가`, `실효 요청 비용 = 기간의 실제 공급자 청구액 / 기간의 식별 시도 수`. 서버비·고정 약정·세금은 따로 보이고, 성공 결과당 비용도 별도 계산한다. 원화 환산은 환율 기준일을 붙인다.
- 현재 공개 요금은 무료 일 500회, Pro 연 €1,000 기본 구간 및 사용량별 조건이 있다. 최소 약정 때문에 €0.005만 곱해 총비용이라고 말하면 안 된다. [공식 요금](https://my.plantnet.org/pricing), [계약 조건](https://my.plantnet.org/terms_of_use). 현재 앱의 일일 제한 기본값(사용자 5회/프로젝트 50회)은 공급자 무료 한도와 별개다.
- 실제 시험은 소규모 연동 확인 → 정확도 표본 → 네트워크별 성능 표본 순서로 예산 내 수행한다. 월간 총액·일일 호출 상한을 두고, 자동 재시도로 초과 사용하지 않도록 한다.

## 6. 구현 순서와 완료 조건

| 순서 | 구현 범위 | 완료 조건/증거 |
|---|---|---|
| 1. 정책·자료 확정 | 대상 종/지역, 보관 기간, 사진 제한, 공급자 조건, 정보 원자료 | 결정 기록, 실제 데이터 필드·라이선스·갱신 계획 확인 |
| 2. 계약과 모의 응답 | v2 스키마·에러·revision·원장 상태 전이 | 정상/불확실/오류 계약 테스트, 기존 v1 회귀 통과 |
| 3. 입력 UX | 저장 전 식별, 품질 안내, 자르기, 최대 3장 | 웹/Mac/Android에서 선택·취소·권한·용량·접근성 검증 |
| 4. 서버 확장 | 다중 사진 검사·중복 제어·TTL·계측·공급자 어댑터 | 동시 중복 요청이 공급자 한 번만 호출, 비밀/사진 로그 없음 |
| 5. 이름·설명 연결 | 버전 목록·동의어·미연결·출처 UI | 검수 표본 이름 일치, 충돌 시 자동 연결 금지, 출처 표시 |
| 6. 저장 연결 | 사용자 선택/미확인 저장, 이전 결과 배제 | 늦은 응답·기록 충돌·삭제·백업 복원 시험 통과 |
| 7. 실제 품질 평가 | 표본·점수 정책 보정·잠긴 평가·비용 대조 | 지표와 신뢰구간, 기기별 p50/p95, 실측 비용 보고서 |
| 8. 제한 베타 | 호출 상한, 장애 시 식별 비활성화, 로컬 기록 유지 | 치명적 결함 없음, 기준 미달 항목 해결 또는 범위 제한 명시 |

모델·정보 목록·게이트웨이의 배포 버전을 남긴다. 출시 가능 조건은 UI 완성과 별개로 실제 식별 평가, Android 실기기 검증, 데이터 이용 조건·보관 안내, 장애 복구 검증까지 충족하는 것이다. 지금의 완료 범위는 이 설계 문서뿐이다.
