# 통합 디자인 품질 검토 · 2026-10-24

## 실제 적용
숲 이미지 중심 홈, 종이색 읽기 영역, 반투명 내비게이션, 입력에만 반응하는 짧은 모션, 최근 관찰로 돌아가기. 예제 기록과 AI 예시 이미지는 표시를 유지한다. 새 폰트·영상·3D·애니메이션 라이브러리를 추가하지 않았다. 온라인 인증/식별 서비스 활성화는 이번 변경에 포함하지 않는다.

## 측정
로컬 production static export, Chromium 새 context, 390×844, serviceWorker 차단, 3회. JS는 해당 화면에서 요청한 압축 해제 바이트 합계이며 전체 앱 크기나 전송 압축 크기가 아니다.

| 지표 | 변경 전 | 최종 변경 후 |
|---|---:|---:|
| 초기 JS | 951,903 B | 900,556 B |
| 예시 사진 2장 합계 | 747,270 B | 227,999 B |
| LCP 3회 | 440 / 736 / 408 ms | 444 / 492 / 652 ms |
| CLS | 약0.00084 | 약0.00082 |

JS 약5.4%, 예시 이미지 약69.5% 감소. LCP 시간 개선은 입증되지 않았으며 로컬 결과를 현장 속도로 일반화하지 않는다. 오프라인 사전 캐시는 나머지 코드도 다운로드하므로 초기 JS 분리는 전체 네트워크 비용 감소가 아니다. 초기 JS 약900KB는 향후 데이터 검증 모듈 등 의존관계를 더 줄일 여지가 있다.

## 검증 결과
- production build와 단위 테스트77개 통과.
- 실제 브라우저7개 통과: 비공개 저장/재관찰, 개인 월간 인쇄, 검수 예시 격리, 360·390·1440px 메뉴/가로넘침/axe WCAG A·AA, 움직임 줄이기/키보드 촬영 진입.
- 독립 QA에서 전환 중 opacity 대비와 홈 예제 표시를 지적해 수정, 재검토 완료.
- expect-cli 실행은 Claude provider 미인증으로 실패. 대신 Playwright·axe 실행. expect 통과로 기록하지 않는다.

## 좋은 앱의 다음 합격선
- 안정성: 사진 처리 실패/취소/저장공간 부족에서도 초안 유실 없이 복구. 실제 모바일 기기 및 장시간 테스트 필요.
- 반응성: 실사용 75백분위 LCP≤2.5s, INP≤200ms, CLS≤0.1 목표. 현재 INP·현장75백분위 미측정. https://web.dev/articles/vitals
- 데이터: 기기 변경·백업복원·탈퇴·사진삭제의 경계를 명확히. 온라인 회원·식별·서버 삭제 실제 왕복은 서비스 설정 후 검증.
- 접근성: 자동 검사 외 Android TalkBack/macOS VoiceOver, 확대·야외 화면 눈부심은 수동 확인 필요.
- 가벼움: 저사양 Android/모바일망/배터리·메모리·긴 기록목록 검증. 무한모션과 사진 위 과도한 blur 금지.
- 운영: 오류 집계는 개인정보 최소 수집 동의/정책 확정 후. 현 단계에 새 추적 SDK를 넣지 않는다.
