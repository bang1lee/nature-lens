# 실제 웹앱 레퍼런스와 적용 결정

조사일: 2026-10-08 KST. 사용자 요청은 실제 웹앱 레퍼런스를 찾아 앱에 반영하는 것이다. 아래는 공식 설명과 브라우저로 확인한 화면에 근거한 설계 결정이며, 구현 여부는 마지막 검증 보고서에서 확인한다. 타 서비스의 사진·브랜드·화면 코드는 복제하지 않는다.

## 화면 설계

기존 화면의 문제는 넓은 데스크톱에서 큰 빈 패널과 중복되는 촬영 버튼, 홈/내 기록의 동일 목적, 출판 작업실 접근의 약한 연결이다. 이 앱은 마케팅 랜딩이 아니라 사진을 계속 쌓는 작업 공간이므로 과한 영웅 이미지·스크롤 연출을 넣지 않는다.

데스크톱은 왼쪽 고정 탐색(관찰 보드·컬렉션·저널·보관/설정·출판 작업실), 오른쪽 제목/주 행동, 검색·필터, 사진 그리드로 구성한다. 빈 화면에는 작은 예시 사진 또는 기존 AI 예시임을 밝힌 관찰 카드와 짧은 시작 문장을 둔다. 실제 사진이 생기면 사용자의 카드가 중심이 된다. 큰 사진과 여백, 명확한 상태가 시각적 특징이다.

색은 기존 디자인 시스템의 paper #F5F2E9, card #FFFEFA, ink #213D32, forest #254F3B, secondary #526353, review #D8CC84를 쓴다. 글꼴은 기존 Noto Serif KR / Noto Sans KR 계열을 유지한다. 버튼·입력은 최소 48px, 모서리는 기존 12px와 카드 4px 규칙을 유지한다. 키보드 초점, 동작 감소, 320/390/1440px 확인을 포함한다.

## 레퍼런스가 구현에 반영됐는지 확인할 기준

- [ ] 보드에서 사진 저장 후 재접속해 기록 찾기까지 가능
- [ ] 검색·필터 0건과 첫 방문 0건이 다른 안내를 제공하고 조건 초기화 가능
- [ ] 관찰 카드에서 사진·날짜·이름·초안/검수 상태를 구분
- [ ] 컬렉션/작업실 접근이 데스크톱에서 명확함
- [ ] 상세 사진과 관찰 메모가 넓은 화면에서 함께 읽힘
- [ ] 로컬 파일 백업과 암호화 임시 전송의 차이를 실제 동작과 일치하게 설명
- [ ] 기존 공개 예시·AI 생성 예시를 실제 사용자 기록이나 식별 증거로 표현하지 않음
