## 화면 구성

### 1. 사진 선택
- 제목: ‘어떤 식물을 만났나요?’
- 기본 행동: [사진 찍기], 보조 [앨범에서 선택]
- 카메라 권한 거절: ‘카메라를 사용할 수 없어요.’ + [앨범에서 선택]. 같은 오류에 긴 설명을 추가하지 않는다.
- 카메라를 쓰는 중에만 촬영 버튼. 카메라 미지원이면 앨범 경로를 먼저 표시한다.

### 2. 사진 확인 + 두 가지 방식

```text
[선택한 사진]                사진 바꾸기

어떻게 알아볼까요?
(●) 지금 알아보기
    AI가 찾은 이름 후보를 바로 확인해요.
(○) 내일의 발견
    먼저 예상하고, 내일 오전9시에 비교해요.
    일치하면 10점 · AI 판단 기준

[계속하기]
사진만 저장하기
기록 더하기 ▾  (메모·날짜·장소)
```

드롭다운 대신 라디오 카드 두 개로 비교. 아이콘에만 의미를 맡기지 않는다. 선택 상태와 설명을 스크린리더에도 제공. 곤충 등 미지원 범위는 선택하는 시점에 한 번 설명하고 식물 모드로 조용히 바꾸지 않는다.

### 3. 로그인과 전송 확인
- 비회원도 촬영·기기 저장 가능. ‘이름 찾기와 예측은 로그인 후 이용해요.’
- 주 버튼 ‘로그인하고 계속’. 로그인 전에 사진/선택 방식을 기기에 저장하고 실패해도 보존. 이메일 링크를 같은 브라우저에서 여는 안내는 링크 요청 후에만 표시.
- 로그인 후에만 전송 동의 표시. 기본 체크 금지. 두 확인은 유지: ‘사람·개인정보가 없는 사진이에요’, ‘사진 전송에 동의해요’.
- 즉시 방식: ‘사진을 Pl@ntNet으로 보내 이름 후보를 찾아요.’ + [사진 처리 안내]. 서버/API/응답시간 같은 운영 용어는 펼침으로 이동.
- 예측 방식: ‘사진은 지금 분석하고, 예상·결과·점수를 서버에 보관해요.’를 동의 근처에 항상 표시. 결과 공개 시점도 유지. 기술적인 해시 설명은 처리 안내로 이동.

### 4. 내일의 발견

```text
어떤 식물일까요?
[예상 이름                     ]
관찰한 단서 더하기 ▾  (선택)

내일 오전9시 공개 · 한국 시간
제출한 예상은 바꿀 수 없어요.
[사진 전송/보관 확인 항목]
[예상 남기기]
점수 규칙 ▾
```

예상 이름은 필수, 이유는 선택임을 명시. 현재 정확한 이름/학명 일치 규칙 때문에 예측 초보자의 오타가 불리하다는 한계를 점수 규칙에서 설명. 자동완성이나 판정 규칙 변경은 별도 기능이며 이번 문구 변경으로 해결됐다고 주장하지 않는다.

대기 화면:
- ‘예상을 남겼어요’ / ‘나의 예상: 민들레’ / ‘10월30일 오전9시 공개’.
- ‘앱에서 다시 확인해 주세요. 별도 알림은 보내지 않아요.’ 한 줄 유지.
- 주 버튼 [내 기록으로]. 공개 시각이 되면 [결과 확인]으로 전환.
- 서버 상태를 확인 중이면 상태만 갱신. 사진/식별을 자동 재전송하지 않는다. 서버 시각으로 판정한다.
- 보조 [지금 확인하기]는 ‘지금 열면 이번 점수는 받을 수 없어요’ 확인창 후 수행. 점수 포기 조건을 숨기지 않는다.

### 5. 결과와 재관찰

```text
[사진]
민들레로 보여요
AI 후보 · 확정된 이름은 아니에요

나의 예상  민들레
예측 점수  +10

[이 이름으로 기록하기]
다른 후보 보기 ▾
같은 식물 다시 기록하기
```

- 예측하지 않은 즉시 결과에는 예상/점수 카드 없음.
- 불확실하면 ‘아직 이름을 알기 어려워요’ + [다른 사진으로 다시 보기] / [이름 없이 저장]. 0점을 오답 단정으로 표시하지 않음.
- ‘먹어도 되는지 판단하는 데 쓰지 마세요’는 결과에 한 번 보인다. 식용/약용 판단 제한은 긴 면책 문구 반복으로 대체하지 않는다.
- 다른 후보를 고르는 UI는 쉽게 접근 가능해야 하며 대표 후보를 확정 종으로 자동 저장하지 않는다.
- 재관찰 단계에서만 ‘지난번과 같은 개체인가요?’를 확인. 전체 설명을 모든 상세 화면에 반복하지 않는다.

## 항상 보이는 것 / 펼쳐 보는 것

항상: 현재 상태, 다음 행동, 로그인 필요 이유, 외부 사진 전송·보관에 대한 핵심 동의, 결과 미확정 표시, 공개 시각, 미리 보기의 점수 포기, 실제 오류와 복구 행동.
펼침: 점수 계산 세부, 공급자·기술 메타데이터, GPS 정밀도와 보관 설명, 추가 후보 상세, 백업·출판·운영 안내.
제거/분리: 사용자 화면의 모의 결과 선택, 중복 문장, 분석 밀리초, 내부 서버 설정 용어.

## 쉬운 이용을 위한 설계 기준

- 기본 본문16px 이상, 주요 터치 영역48×48px 이상을 목표로 한다. 필수 정보는 색/아이콘만으로 구분하지 않는다.
- 기본 설명은 제목 아래 한 문장. 상태별 주요 버튼은 하나, 보조 행동은 최대 두 개를 목표로 한다. 필수 동의/입력 라벨은 이 제한 때문에 생략하지 않는다.
- 위치는 선택. 위치 오류는 장소 항목 안에만 나타나고 ‘위치 없이 계속’ 제공. 식별 오류처럼 보이지 않도록 분리한다.
- 제목, 입력 라벨, 현재 선택, 펼침 상태, 진행 중 상태를 보조기기로 읽을 수 있게 한다. 키보드 포커스를 다음 상태로 이동하고 뒤로 가기에서 사진/예상을 보존한다.
- 200% 글자 확대, 320px 폭, 화면 읽기, 키보드만 사용, 느린 연결에서 검증한다. 긴 한국어/학명/에러에도 가로 스크롤이나 버튼 겹침이 없어야 한다.
- 모션 줄이기 설정 존중. 정보 공개와 점수 표시는 애니메이션이 끝나야 읽을 수 있는 구조로 만들지 않는다.

## 구현 순서와 완료 조건

1. **저위험 정리:** 중복 안내 제거, 시연 분리, GPS/세부 정보 접기, 상태별 문구. 실제 동의 의미와 로그인 규칙 보존.
2. **행동 흐름 연결:** 두 카드 선택 → 자동 기기 보존 → 로그인 → 선택한 흐름 복귀. 저장 실패 시 로그인 이동/사진 전송을 하지 않음. 기존 onApplied/로그인 복귀 계약과 보관 데이터 호환성 검사.
3. **대기·결과 화면:** 다음날 공개, 조기 공개, 채점 보류, 로그아웃/다른 계정, 결과 적용, 재관찰을 각각 별도 상태로 검수.
4. **홈·설정 정돈:** 내 행동 우선. 시연·공동관찰·출판 기능 삭제가 아닌 명확한 진입점 제공.

검증 목표(아직 달성 주장 아님):
- 390×844에서 기본 사진 확인→주요 진행 버튼을 찾는 데 긴 안내 스크롤이 필요하지 않음. 설명 텍스트의 기본 노출량을 현재 대비 약40% 줄이는 목표를 두되 동의/오류/접근성을 우선.
- 비회원 저장, 로그인 복귀, 전송 동의, 실제/시연 구분, 다음날 서버 시각, 중복 적립 방지, 후보 선택, 재관찰 및 백업 호환 기존 검사 모두 통과.
- 첫 사용자5명(디지털 숙련도가 서로 다른 참여자)의 과제 관찰: 설명 없이 사진 저장·즉시 식별 진입·내일 예측 진입·GPS 실패 복구. 목표4명 이상 독립 완료, 오해/막힘 기록 후 수정. 이 계획만으로 ‘모든 사람이 사용 가능’하다고 결론내리지 않는다.

배포 전 대표 화면(사진 확인/예상 입력/대기/결과) 비교 검수. 새 디자인 테마나 식별·채점 모델 변경은 포함하지 않는다.
