# PictureThis 참조 · 무가입 베타 실동작 복구

기준 e5e4134, 사용자 2026-11-16 구현 재개 승인. 아침 목표는 2026-11-17 KST 오전. 예약 작업을 만들지 않고 현재 작업에서 구현·검증·배포까지 진행한다. 그 시점까지 성공을 미리 약속하거나 백그라운드 실행을 위장하지 않는다.

## 완료 계약
1. 이메일·비밀번호 없이 명시적인 식별 행동으로 익명 기기 인증 세션을 생성한다. 기존 회원 세션을 교체하지 않는다.
2. 사진 선택→짧은 전송 확인→바로 식별, 결과까지 추가 저장/로그인 버튼 없음. 처리 실패·취소·할당량 초과는 사진 보존 및 재시도로 연결한다.
3. 공개 동의 이후 실제 Storage 객체와 기록을 저장한다. 서버 재조회/해시·소유권 검사 전 성공으로 보고하지 않는다. 기존 로컬 기록을 자동 전송하지 않는다.
4. 예측·점수는 회원 전용, 익명 세션별 일일 제한과 프로젝트 전체 영속 제한 유지. 익명 계정 재생성으로 개인별 제한은 리셋될 수 있음을 운영 한계로 기록한다.
5. 모의 검사·실제 사진의 Pl@ntNet 응답·실제 서버 저장·운영 배포를 각각 증거로 분리한다. 공개 테스트 사진에는 사람/위치/개인정보가 없고 외부 시험에 사용 가능한 공개 자료만 사용한다. 기존 한국 평가 사진·사용자 사진은 전송하지 않는다.

## 병렬 소유권
- research: PictureThis 공식 자료 조사와 차이 표. 내부 모델/성능 추정 금지.
- guest_backend(Terra6.1 max): server, auth 및 제한 검사. 회원 예측 유지.
- guest_capture(Terra6.1 max): QuickCapture/IdentificationPanel/Access 및 공통 guest helper. 사용자 명시 행동으로만 전송.
- guest_storage(Terra6.1 max): BetaPhotos/beta-public 및 업로드·복원 검사.
- root: 운영 정책, 회원 UI 경계, 실서비스 설정, 통합, 배포 및 실측.
공유 저장소에서 다른 작업자의 변경을 되돌리지 않는다. 모델 설정/연구 코어 유지.

## 실행 프롬프트
“문서나 모의 PASS로 사용자의 증상을 해결했다고 보고하지 말 것. 맡은 경로에서 원인→최소 수정→실패/재시도·중복·권한 회귀 검사를 수행할 것. 사진이 서버에 있다는 주장은 서버 객체와 기록 재조회로, 식별 성공은 공급자 응답으로, 배포는 운영 URL과 배포 ID로만 뒷받침할 것. 키·토큰·사용자 사진을 보고서에 넣지 말 것. 의존 작업과 인터페이스를 먼저 합의하고, 원격 변경은 root만 수행할 것.”

## 그래프와 검사 루프
현재 Git/원격 확인 → 독립 조사·서버·UI·저장 구현 → 공유 계약 합류 → 회귀 검사 → 익명 설정/DB 검사 → 원격 서버·웹 배포 → 실제 무가입 식별·공개저장·재조회 → 결과 보고.
실패는 코드/서비스설정/공급자/네트워크로 구분. 동일 실패 수정 최대2회 후 원인과 다음 조건 기록, 독립 작업 계속. 재시도 비용과 중복 업로드를 성공으로 숨기지 않는다.
