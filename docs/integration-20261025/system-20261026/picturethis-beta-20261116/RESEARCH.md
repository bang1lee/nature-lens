# PictureThis 공개 UX 조사 · 2026-11-16

## 범위와 근거 수준

공식 웹 FAQ와 미국 App Store 공개 설명을 읽고, Nature Lens 현재 소스의 촬영·식별·저장 흐름과 비교했다. 앱 바이너리, 로그인된 네이티브 앱, 내부 트래픽은 제공되지 않았다. 따라서 디컴파일·비공개 API·실제 응답시간·현재 네이티브 화면 배치를 확인했다는 주장은 하지 않는다. 공개 설명 기반 행동 분석이며 화면 복제 작업이 아니다. 타사 사진·아이콘·문구 자산을 가져오지 않는다.

조회한 공개 문서는 현재 접근 가능하지만 FAQ 자체의 갱신일은 확인되지 않았다. 아래 내용은 공식 문서상 동작이며 현행 앱 실측과 구분한다.

## Nature Lens 변경 전 확인

검토 파일: `src/components/mobile/QuickCapture.tsx`, `IdentificationPanel.tsx`, `BetaPhotos.tsx`. 아래는 해당 파일을 읽은 시점의 소스 동작이며 배포판 실험 결과가 아니다.

| 영역 | 현재 동작 | 사용자가 겪는 틈 |
|---|---|---|
| QuickCapture | 사진 선택 후 확인 방식 선택. `바로 확인하기`가 `save(true)`를 호출해 기기 기록을 저장하고 별도 IdentificationPanel로 이동한다. | 버튼을 눌러도 식별 요청이 시작되지 않는다. 바로 확인이라는 기대와 실제 단계가 다르다. |
| IdentificationPanel | 서비스 준비, 로그인, 전송 동의 두 항목을 확인한 후 별도 `이름 후보 찾기`를 눌러 요청한다. | 앞 화면에서 이미 확인을 선택했는데 같은 목적의 버튼을 다시 만나고 이메일 로그인이 개입한다. 실패·취소·후보 상태가 구분되는 장점은 보존해야 한다. |
| BetaPhotos | 기기 저장과 별개의 공개 업로드. `is_anonymous` 세션을 배제하고 이메일 로그인 후 공개 동의를 받는다. 공개 성공은 서버 처리 뒤 표시한다. | 첫 기록 저장이 서버 업로드라고 느끼기 쉽다. 무가입 사용자가 서버 보관을 마칠 수 없다. |

공개 업로드는 기존 설계상 사진·제목·이름·관찰일·메모를 노출한다. 이를 단순히 `저장`으로 줄이면 안 된다. 서버 보관과 공개 게시가 현재 결합되어 있음을 짧고 명확하게 알려야 한다.

## 우선 개선 3개

1. **사진 다음 화면에서 식별을 끝낸다.** 사진 미리보기 아래 주 버튼을 `이름 찾기`로 둔다. 필요한 전송 안내·동의를 같은 화면에서 받고 한 번 누르면 요청을 시작한다. 기기 임시 저장은 조용히 선행할 수 있으나 그것만으로 식별 완료를 표시하지 않는다. 결과는 같은 화면에 사진, 후보 이름, 미확정 표시, `이 이름으로 기록` 순서로 보여준다. `내일 알아보기`는 별도 학습 목적 선택으로 남긴다.
2. **가입 없는 베타를 기기 세션으로 연결한다.** 사용자는 이메일 입력 없이 촬영·식별·공개 동의 후 서버 저장을 완료한다. 서버는 기기별 유효 인증 세션, 소유권, 요청 한도, 중복 방지를 유지한다. 익명 공유키만으로 쓰기를 허용하는 방식은 이 권고가 아니다. 이메일 연결은 나중의 기기 변경·복구 선택으로 둔다. 기존 회원 예측·점수 정책을 자동으로 확장하지 않는다.
3. **저장 위치를 결과로 증명한다.** `기기에 보관됨`과 `서버에 공개 저장됨`을 구분한다. 주 동작은 공개 동의 후 `공개로 저장`, 처리 중 `서버에 저장 중…`, 실제 성공 뒤 `서버에 저장했어요`로 표시한다. 실패하면 사진과 결과를 유지하고 `다시 저장`을 제공한다. 공개 피드 재조회와 내 서버 기록으로 이어지는 확인 동선을 둔다.

위 권고는 공개 자료에서 도출한 Nature Lens 설계 판단이며 PictureThis의 내부 구현에 대한 설명이 아니다. 숲색·종이색·기존 간격과 카드 컴포넌트를 유지하고 문구·행동 순서·상태 전달만 정리한다.

## 최소 사용자 흐름과 문구

`사진 찍기 / 사진 선택` → 사진 미리보기 + `이름 찾기` → `이름을 찾고 있어요…` → 후보 또는 판단 유보 → `이 이름으로 기록` / `이름 없이 기록` → 공개 범위 확인 → `공개로 저장` → `서버에 저장했어요`.

전송 전 한 줄: `사진을 식별 서비스로 보내 이름을 찾아요.` 자세한 처리 안내는 기존 링크 유지. 공개 전 한 줄: `사진과 기록이 모두에게 보여요.` 공개 취소 미지원 등 실제 중요한 제한은 접힌 안내에만 숨기지 않는다. 네트워크 실패: `사진은 기기에 보관했어요. 연결 후 다시 시도해 주세요.` 실제 분석 소요시간을 측정하기 전 `즉시` 또는 고정 초 단위 약속을 하지 않는다.

## 완료 기준

- 새 브라우저에서 이메일 입력 없이 유효 기기 세션을 얻고, 동의 후 실제 식별 서비스에 한 번 요청해 결과를 받는다. 기존 로그인 회원 경로도 유지한다.
- 사진 선택부터 식별 요청까지 한 주 버튼으로 연결한다. 재렌더링·더블 탭이 분석 요청이나 기록을 중복 생성하지 않는다.
- 취소·타임아웃·오프라인·미지원·판단 유보에서 사진을 잃지 않는다. 저장/전송 실패를 성공 문구로 덮지 않는다.
- 서버 성공은 응답뿐 아니라 저장 객체와 기록 재조회로 확인한다. 새로고침 후 내 서버 기록에 남고 공개 동의한 사진만 피드에 나온다.
- 기기 세션 소유권과 다른 사용자의 수정 차단을 검증한다. 기기 데이터 초기화 시 익명 기록 복구 범위를 정확히 알린다.
- 모의 검사, 실제 공급자 분석, 실제 서버 저장, 배포 확인은 각각 별도로 보고한다. 이 조사 문서는 그 실검증을 대신하지 않는다.

## 운영 계약 연결

`PLAN.md`에는 2026-10-29 회원 식별 계약과 미로그인 전송 금지 조건이 남아 있다. 이번 무가입 베타 구현은 새 사용자 요청 범위의 변경이므로, 기기별 인증 세션을 쓰는 베타 식별·서버 저장과 기존 회원 예측·점수 경계를 주 담당자가 명시해야 한다. 본 조사에서는 운영 설정·앱 소스·배포를 변경하지 않았다. OpenRig identity 명령은 현재 환경에 CLI가 없어 실행되지 않았다.
