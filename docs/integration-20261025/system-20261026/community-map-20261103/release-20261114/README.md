# 공동 관찰 지도 실서비스 적용 준비 · 2026-11-14

사용자는 실서비스 적용과 공개 구역 등록·실시간 검증을 승인했다. 원격 변경은 주 담당자가 수행한다. 이 폴더는 로컬 준비 자료다.

## 적용 순서와 중단 조건

1. 프로젝트 대상을 확인한 뒤 `preflight.sql`을 읽기 전용으로 실행한다. 기존 제출 테이블·피드와 `supabase_realtime` publication이 있고 `puballtables=false`여야 한다. 지도 테이블·컬럼·함수·트리거와 지도 publication 항목은 모두 없어야 한다. 원본 `community_submissions`가 publication에 포함되어 있거나 기존 객체가 일부라도 있으면 원인과 설정을 먼저 검토한다. REST 404만으로는 스키마 부재가 확정되지 않는다.
2. 위 조건에서 `supabase/migrations/20261103000000_community_map.sql`을 SQL 편집기로 한 번 실행한다. 트랜잭션으로 묶여 있지만 멱등이 아니므로 오류 후 동일 내용을 무작정 다시 실행하지 말고 preflight를 재확인한다. publication이 없거나 모든 테이블에 적용되는 경우 자동으로 변경하지 않는다.
3. `seed.sql`은 선택한 공개 구역이 없으면 추가하고 같은 값이 이미 있으면 유지한다. 같은 ID에 다른 값이 있으면 전체 트랜잭션이 실패한다. 좌표는 대표 구역의 계산된 중심이지 실제 관찰 좌표가 아니다.
4. `postcheck.sql`에서 두 RLS 활성화, 지정된 정책·트리거·publication, 공개 구역, ineligible_points=0을 확인한다. 권한 결과는 순서대로 true/false/false/false/true/false여야 한다. 익명 API에서 공개 구역과 점 목록 조회, 비공개 테이블 접근 거부를 별도로 확인한다. SQL 보기는 privileged라서 사용자 권한 확인을 대체하지 못한다.

## 실시간 왕복 실험

실제 관찰을 건드리지 않는다. 발행 전 또는 별도 통제 환경에서 두 브라우저 세션을 사용한다. A는 공개 지도를 열고 점 목록 조회 후 Realtime SUBSCRIBED를 확인한다. B는 전용 임시 테스트 계정으로 '실시간 연결 시험 · 합성 기록'이라는 표시가 뚜렷한 합성 기록을 공개 구역·각 동의와 함께 제출한다. 공개 피드에 표시될 수 있으므로 실제 이름이나 사진 대신 작은 합성 이미지와 합성 텍스트만 사용한다. 관리자는 **이 시험 레코드 ID만** 검사해 상태를 승인하고, A에서 30초 폴링이 아닌 이벤트 직후 재조회로 표시되는지 네트워크 이벤트·시간을 구별해 확인한다. 이어 B에서 시험 제출을 철회하고 A에서 제거 이벤트와 재조회를 확인한다. 지연·실패 시 폴링으로 보인 것을 실시간 성공으로 간주하지 않는다. 마지막으로 테스트 점·제출·시험 계정의 부재를 읽기 전용으로 검증한다. 중간 실패 시에도 해당 테스트 계정/레코드만 정리하며 실제 사용자 데이터는 수정하지 않는다. 실제 공개된 합성 기록이 잠시 존재할 수 있다는 운영 영향을 기록한다.

## 확인 결과와 운영 조건

- 격리 PGlite 메모리 DB에서 기본 마이그레이션, 지도 마이그레이션, 동일 seed 두 번, SQL 단언 12개 통과. 다음 명령으로 재현한다: `npm install --prefix /tmp/nature-map-pg @electric-sql/pglite --no-save --ignore-scripts` 후 저장소 루트에서 `node docs/integration-20261025/system-20261026/community-map-20261103/release-20261114/pglite-check.mjs`. 이는 Supabase 서버·실시간 논리복제·동시 세션 경합 테스트가 아니다.
- `npm run build`, `npm run graph:local`, `npm run verify:local` 성공. 지도 브라우저 테스트 3건과 axe 통과. 브라우저 자동화는 OSM 서버 대신 합성 타일을 사용한다. `expect-cli`는 Claude 인증 부재로 실행 실패했다.
- 지도 출처는 [OSM 타일 정책](https://operations.osmfoundation.org/policies/tiles/)에 맞춰 저작권 링크를 보이도록 수정했다. 일반 웹 요청의 Referer와 브라우저 캐시를 배포 환경에서 확인해야 한다. OSM 타일 서비스는 가용성이 보장되지 않으며 미리 받기·오프라인 지도에 사용할 수 없다. 운영 규모가 커지면 명시적 이용 조건을 가진 타일 공급자나 자체 호스팅을 선택한다. 앱의 오프라인 캐시는 외부 타일을 저장하지 않는다.
- MapLibre 데모 글꼴 요청을 제거했다. 묶음 원의 기록 수는 지도 아래 구역 목록에 표시된다. 실제 지도 타일, 실제 배포와 실시간 이벤트는 이 로컬 검사에 포함되지 않는다.

## 2026-11-14 실제 데이터베이스 읽기 전용 확인

사용자가 승인한 마이그레이션과 공개 구역 등록 이후, 별도의 익명 Supabase 클라이언트 두 개로 조회·구독만 확인했다. `.env.local`의 공개 URL과 공개 키는 프로세스 메모리에서만 사용했으며 값은 기록하지 않았다.

- `map_areas` REST 200, `anseong-cheongnyangsan-area`의 활성 여부·대표 좌표·반경이 제안값과 일치했다.
- `community_map_points` REST 200, 최대 1건 표본 조회 결과 0건이었다. 원본 제출 테이블의 익명 REST 요청은 401로 거부됐다.
- 서로 독립된 두 클라이언트의 `community_map_points` 변경 구독이 각각 `SUBSCRIBED` 상태를 반환했고 채널을 정리했다.
- 생성·철회 이벤트를 보내지 않았으므로 실제 이벤트 전달, 반영 시간, 승인·철회 왕복은 아직 검증하지 않았다. 구독 성립은 이벤트 전달 성공을 뜻하지 않는다.

저장소 루트에서 `node docs/integration-20261025/system-20261026/community-map-20261103/release-20261114/verify-live-readonly.mjs`로 재확인할 수 있다. 이 스크립트는 공개 키를 출력하지 않고 구역 일치 여부·상태·표본 개수·구독 결과만 출력한다.
